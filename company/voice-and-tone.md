# Voice & Tone

> Purpose: How the brand sounds in words. An AI uses this to write copy that reads like the brand, not like generic marketing.

## Voice in three words

**Clear.** Explain the system in plain language before introducing frameworks.

**Structured.** Make the next step, source of truth, and review path obvious.

**Practical.** Avoid vague inspiration. Tie every idea to a use case, decision, or workflow.

## Tone by context

| Context | Tone | Example phrasing |
|---------|------|------------------|
| Homepage / hero | Confident and plainspoken | Turn scattered brand context into a usable design-system handoff. |
| Product / feature pages | Explanatory and specific | Package voice, assets, code references, and Figma notes before design work begins. |
| Forms and microcopy | Direct and reassuring | Add the source file, then note what the reviewer should inspect. |
| Error / empty states | Calm and corrective | This asset is not in the manifest yet. Add it before referencing it in output. |
| Email and nurture | Helpful and concise | Here is the context bundle, the open gap list, and the recommended next action. |

## Writing rules

- Reading level: plain professional language, roughly 8th-10th grade.
- Sentence length: short to medium; avoid long nested qualifiers.
- Person/POV: use "you" for the reader and "we" for the brand when appropriate.
- Numbers and data: use only when a source is available.
- Claims: qualify claims when evidence is incomplete.
- CTAs: make the next action concrete.

## Voice QA checklist

- Does the copy explain what the system does in plain language?
- Does it avoid unsupported claims?
- Does it name the next action?
- Does it preserve source-of-truth discipline?
- Does it sound like a senior operator, not a hype-driven SaaS ad?
