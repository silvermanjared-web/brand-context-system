# Component Contracts

These component contracts translate the demo context into reusable implementation guidance.

## Button

Use semantic color tokens. Primary buttons use the accent token with sufficient text contrast. Focus state must remain visible. Disabled state must not rely on color alone.

## Card

Cards use surface, spacing, and radius tokens. Information hierarchy should remain legible without decorative treatment.

## Hero

The hero must communicate one primary proposition, one primary action, and no more than one supporting action. Copy must follow the voice rules in `company/voice-and-tone.md`.

## Form

Labels remain persistent. Validation errors must be explicit. Required fields are indicated in text, not color alone.

These are public demo contracts, not a production component library.
